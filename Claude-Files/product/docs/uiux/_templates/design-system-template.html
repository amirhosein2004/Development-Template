11. Accessibility baseline (WCAG 2.2 AA)

  • Body text contrast ≥ 4.5:1; UI ≥ 3:1; focus ring ≥ 3:1.
  • Every focusable shows a visible ring (never outline: none without a replacement).
  • Every action reachable + operable by keyboard.
  • Uses WAI-ARIA APG patterns verbatim; roles are not invented.
  • Respects prefers-reduced-motion, prefers-contrast, prefers-reduced-transparency.
  • Target size ≥ 24×24 (SC 2.5.8); 44×44 recommended.
  • Skip-to-content is the first focusable element on every page.

12. RTL / directional rules

  • CSS logical properties only — margin-inline-start, padding-inline-end, inset-inline-start — never left/right.
  • Sidenav sits on the reading-start edge.
  • Directional icons mirror via transform: scaleX(-1) under [dir="rtl"].
  • Numbers, URLs, code isolate via <bdi>.
  • Machine feeds (JSON-LD, RSS, <time datetime>) always use ASCII digits + ISO 8601 Gregorian.

These are skeleton answers, not product answers

Every row below is a value the foundational tokens (§1–§7) do not answer on their own — header height, sidebar width, footer columns, grid gap, mobile nav pattern, motion mapping, SEO placement, and so on. Two teams building from the same tokens can produce visually incoherent surfaces if these decisions aren't pinned. The values here are chosen to make the skeleton runnable; they are not recommendations for your product. Override per product, then remove the value tag from each row you consciously accept.
