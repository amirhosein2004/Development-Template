# {{PROJECT_NAME}} — business/docs

The **business/docs** layer for **{{PROJECT_NAME}}** — brand identity, competitor research, and canonical legal/founding documents. Every project-specific fact here (product name, positioning, segments, local-market dimension) is derived from `../product/docs/product.md`, which is the single source of truth. This file is generated by `/business-audit init`; edit `product.md` and re-run to refresh.

Three recurring prompts drive this repo:

- **"Analyze this competitor."** → one dated `analysis.md` per site under a segment/slug folder, scored on 28 capability dimensions.
- **"Extract the features."** → one dated `feature-catalog.md` — union of every concrete feature observed across audits, categorized by the same 28 dimensions, each carrying a strategic-priority score.
- **"Extract the roles."** → one dated `roles.md` — every user role, persona, or audience the competitors explicitly model, cited back to the audits that surfaced it.

Everything is snapshot-dated (`YYYY-MM-DD`) so re-audits stack alongside prior runs instead of overwriting them.

## How to use

1. **Product identity first.** Run `/product-init` once to create `../product/docs/product.md`. Every other command reads from there.
2. **Business scaffold.** Run `/business-audit init` — fills this `README.md` and `CLAUDE.md` from `product.md`. `competitor-analysis/AUDIT_PROMPT.md` is project-agnostic and never touched.
3. **Discovery.** Run `/business-audit discover` — sweeps the four channels (local direct, global reference, regional peers, adjacent substitutes) and writes `competitor-analysis/YYYY-MM-DD-discovery.md`.
4. **Per-competitor audit.** Run `/business-audit audit` — loops the per-competitor audit over every `verdict: audit` row.
5. **Synthesis.** Once ≥3 `analysis.md` files exist under the snapshot date, run `/business-audit synthesize` — writes feature-catalog + comparison-and-ranking + roles for that date.

## Snapshot dating (why every file is `YYYY-MM-DD`)

Re-audits **add** a new dated folder or a new dated file — they never overwrite the previous one. This preserves the diff over time (how a competitor evolved, how the market shifted). Never rename a past-dated file "for tidiness"; never edit a past-dated audit. If a factual correction is needed, add a new dated run and let the diff show the delta.

## What lives outside this repo

`business/docs/` owns **market intelligence, brand identity, and canonical legal/founding documents**. It does **not** own:

- **Product identity & positioning** — that belongs in `../product/docs/product.md` (single source of truth).
- **Product scope per release** — that belongs in `../product/docs/features/v{N}/` (only `[x]` items ship).
- **Engineering documentation** — that belongs in `../tech/docs/`.
- **Cross-repo standards** (git, branching, MR flow, review rubric) — those belong in the umbrella `docs/standards/`.

When you feel tempted to add a "roadmap" or "architecture" file here, stop and put it in the correct repo.
